# Архитектурные решения (DECISIONS.md)

## Решение 1: Защита внутренней коллекции через `List.copyOf`

**Проблема.** `getItems() { return items; }` отдаёт ссылку на изменяемую коллекцию. Внешний код может вызвать `add`/`remove` в обход `Order.addProduct` / `removeProduct`, нарушив объединение повторного товара и запрет модификации после `confirm()`.

**Решение.** `getItems()` возвращает `List.copyOf(items)`. Состав заказа меняется только через методы `Order`.

**Следствие.** `order.getItems().add(...)` бросает `UnsupportedOperationException`. Инкапсуляция `items` закрыта.

## Решение 2: Лимит количества в одной константе

**Проблема.** Вариант 1 меняет лимит на 110. Дублирование числа по классам ломает изменение на защите.

**Решение.** `OrderItem.MAX_QUANTITY = 110` — единственное место с порогом. `Order.addProduct` и `OrderItem.validateQuantity` читают только его.

**Следствие.** Изменение лимита — одна строка в одном классе.
